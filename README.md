# noobtunnel

A self-hosted WireGuard mesh in one binary. A **control node** on your VPS, an
**agent** on every machine you want on the mesh, and a dark-mode web UI to run it.

- **Agents dial out, so they need no open ports**, no port forwarding and no
  firewall holes. One command installs one, as a root-owned systemd service.
- **Every machine gets an address** (default `10.77.0.0/16`) and can reach every
  other one, from anywhere. Traffic goes **directly** between agents when their
  NATs allow it and through the control node otherwise, automatically.
- **The web UI** shows the mesh, live handshakes and traffic, and lets you enroll
  agents, publish services, manage accounts and read the logs.
- **Publish services** through any agent - HTTP, HTTPS, TCP or UDP - on the
  control node's public address, without exposing the machine behind it.

WireGuard does the data plane (kernel implementation, ChaCha20-Poly1305) with
per-agent and per-pair preshared keys generated by the control node.

## Install the control node

One command on a fresh Ubuntu/Debian server whose domain points at it. It asks a
few questions (domain, email, ports, admin password), checks every answer, then
installs itself and gets the certificate:

```sh
curl -fsSL https://raw.githubusercontent.com/hinoobers/noobtunnel/main/scripts/install-server.sh | sudo bash
```

Your UI is then on `https://your-domain`, with no port in the address. Port 8443
is only what agents dial.

Ports to have open on the server: 443/tcp (you, over your domain), 8443/tcp
(agents), 80/tcp (the certificate check) and 51820/udp (the mesh itself).

## Update it

One command, no questions. Your configuration, accounts, keys, certificates and
published services stay as they are; the binaries are replaced and the service is
restarted:

```sh
curl -fsSL https://raw.githubusercontent.com/hinoobers/noobtunnel/main/scripts/update-server.sh | sudo bash
```

## Add an agent

Click **Add agent** in the UI, give it a name, choose whether it should run as a
systemd service or a Docker container, and run the command it hands you on the
machine you want on the mesh:

```sh
curl -fsSLk --retry 3 https://your-domain:8443/install.sh | sudo sh -s -- --server your-domain:8443 --token nt_... --fingerprint 12:34:... --name homelab
```

The button writes that line for you, with the real token, pin and fingerprint —
add `--docker` to it for the container (run it in the directory the container
should live in, and it offers to install Docker if the machine does not have it).
The agent appears in the UI within seconds and needs nothing opened on its side.

To update an agent later, in the agent's directory or on the machine itself:

```sh
curl -fsSLk https://your-domain:8443/install.sh | sudo sh -s -- --update
```

It fetches the newest agent binary and restarts the container or the service. The
machine keeps its identity and address, so there is no token to paste and nothing
to re-enroll. The UI shows that command next to every install command.

## Remove it

One command. It lists everything noobtunnel put on the machine, asks once, then
deletes all of it:

```sh
curl -fsSL https://raw.githubusercontent.com/hinoobers/noobtunnel/main/scripts/uninstall-server.sh | sudo bash
```
